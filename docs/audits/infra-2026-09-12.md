Program-level findings belong to `/audit-solana` and are not duplicated here.

## What is already right

Worth recording, because an auditor will ask and the answers are good:

- **Every SQL statement is parameterised.** 120 `prepare()` calls, no user input
  ever concatenated into SQL.
- **Every chain-supplied string is escaped.** Token names, NFT names and booking
  names all pass through `escapeHtml` before reaching `innerHTML`. Of 15
  `innerHTML` sites interpolating variables, all 15 interpolate numbers, base58
  addresses, or `encodeURIComponent` output.
- **The advertising banner — the one place a paying stranger supplies content —
  is rendered with `textContent`, not `innerHTML`**, is https-validated
  server-side, is length-capped, and drops back to `approved = 0` on every edit
  so it cannot run without review.
- **The production worker has zero npm dependencies.** No supply chain in the
  code path that serves users.
- **CSP omits `'self'` from `script-src`**, so even a file uploaded to the site's
  own origin cannot execute. Only `cdn.jsdelivr.net` is allowed.
- **CORS is a strict allowlist** — `https://solquicks.com` only; a foreign origin
  gets no `Access-Control-Allow-Origin` at all.
- **Sign-in is sound.** 256-bit CSPRNG nonce, 5-minute TTL, deleted on use
  (replay-proof), ed25519 verified server-side, 256-bit session tokens.
- **Payments verify on-chain**, are USDC-only, and every signature is recorded so
  it cannot be replayed against a second booking.
- **IP addresses are never stored** — used transiently for rate limiting only.

## Findings

### ~~[HIGH] INFRA-01: The site can be framed~~ — FIXED 2026-09-12
**Confidence:** 9/10 · **Phase:** 6 — OWASP A05 · **Category:** Misconfiguration / STRIDE-Spoofing
**Location:** response headers for `https://solquicks.com/` (no deploy config in repo)

**Description:** No `X-Frame-Options` and no `frame-ancestors` directive. The CSP
is delivered in a `<meta>` tag, and `frame-ancestors` is ignored there by
specification — it only works as a real HTTP header. Any site can embed
solquicks.com in an invisible iframe. This matters more than usual because the
page asks people to approve wallet transactions.

**Exploit scenario:**
1. Attacker builds `free-moon-rangers-airdrop.example` and iframes
   solquicks.com invisibly, positioned under a "Claim airdrop" button.
2. The victim clicks the decoy; the real click lands on **Pay with connected
   wallet** or **Burn and close**.
3. The wallet prompt appears from the genuine origin, so every warning sign a
   user is taught to check looks correct. They approve.
4. Funds move, or tokens burn, from a click the user believed was something else.

**Evidence:** `curl -sI https://solquicks.com/` returns no framing header;
`grep -c frame-ancestors index.html` → 0.

**Remediation:** the site is served by Vercel, so add `vercel.json`:
```json
{ "headers": [ { "source": "/(.*)", "headers": [
  { "key": "X-Frame-Options", "value": "DENY" },
  { "key": "Content-Security-Policy", "value": "frame-ancestors 'none'" },
  { "key": "X-Content-Type-Options", "value": "nosniff" },
  { "key": "Referrer-Policy", "value": "strict-origin-when-cross-origin" },
  { "key": "Permissions-Policy", "value": "camera=(), microphone=(), geolocation=(), payment=()" }
] } ] }
```
**Status:** FIXED. `vercel.json` now sends `X-Frame-Options: DENY` and
`frame-ancestors 'none'` (plus nosniff, referrer and permissions policies).
Confirmed live on solquicks.com.
**Priority:** ~~P0~~ done.

### ~~[HIGH] INFRA-02: web3.js loads from a CDN with no integrity check~~ — FIXED 2026-09-12
**Confidence:** 8/10 · **Phase:** 2 — Supply chain · **Category:** OWASP A08 Integrity Failures
**Location:** `index.html:~20`, and the same line in `stake-init.html`, `fix-names.html`

**Description:** `@solana/web3.js@1.98.0` is pulled from `cdn.jsdelivr.net` with
no `integrity` attribute. The version is pinned, which prevents the ordinary
"latest moved under us" problem, but it does not protect against the CDN serving
different bytes. This script builds and signs every transaction on the site.

**Exploit scenario:**
1. jsDelivr is compromised, or DNS/BGP for the CDN is hijacked for a window.
2. A modified `index.iife.min.js` is served to solquicks.com visitors.
3. The modified library rewrites the recipient inside `TransferChecked` before
   the wallet is asked to sign, or leaks whatever it is handed.
4. Users approve a transaction whose displayed intent and real effect differ.
   The site's own code is untouched, so nothing looks wrong locally.

**Evidence:** `grep -c "integrity=" index.html` → 0.

**Remediation:** add SRI, or self-host the file (self-hosting also removes the
third party entirely, at the cost of manual updates):
```html
<script src="https://cdn.jsdelivr.net/npm/@solana/web3.js@1.98.0/lib/index.iife.min.js"
        integrity="sha384-<hash>" crossorigin="anonymous" defer></script>
```
Generate with:
`curl -s <url> | openssl dgst -sha384 -binary | openssl base64 -A`
**Status:** FIXED. Both jsDelivr scripts carry sha384 integrity hashes,
verified against the npm registry tarball before pinning. Browser-checked: the
correct hash loads and a wrong hash on the same URL is refused, so enforcement is
real. The runtime-injected QR library is pinned in code.
**Priority:** ~~P0~~ done.

### [MEDIUM] INFRA-03: Missing hardening headers; HSTS is not preload-grade
**Confidence:** 9/10 · **Phase:** 6 — OWASP A05
**Location:** hosting configuration

**Description:** `strict-transport-security: max-age=63072000` is present but has
no `includeSubDomains` and no `preload`. `X-Content-Type-Options`,
`Referrer-Policy` and `Permissions-Policy` are absent. None of these is
exploitable alone; together they are what a checklist-driven audit fails you on.

**Status:** FIXED 2026-09-12. All three headers ship, and HSTS now carries
`includeSubDomains` — verified only `www` exists and it is HTTPS. `preload` is
deliberately left off: it is a browser-preload-list commitment that takes months
to reverse and should be a decision, not a side effect. Live response carries
exactly one HSTS header.
**Priority:** ~~P1~~ done (bar preload, deferred by choice).

### [MEDIUM] INFRA-04: Production deploys from an unprotected branch with no CI
**Confidence:** 9/10 · **Phase:** 3 — CI/CD · **Category:** OWASP A08 / STRIDE-Tampering
**Location:** GitHub `solquicks/solquicks`, `main`

**Description:** The repo is public, has **no** workflows, and `main` has **no**
branch protection — `GET /branches/main/protection` returns "Branch not
protected". Vercel deploys `main` automatically. There is no review gate, no
required check, and no signed commits between a push and live code on a page
where users sign transactions.

**Exploit scenario:**
1. The GitHub account or a token with repo scope is phished or leaked.
2. The attacker pushes one commit to `main` altering the transaction-building
   code — or simply the treasury address constant.
3. Vercel publishes it within a minute. There is no approval step and no CI to
   notice.

**Evidence:** `gh api repos/solquicks/solquicks/branches/main/protection` → 404
Branch not protected; `ls .github/workflows` → absent.

**Status:** PARTLY FIXED 2026-09-12. Secret scanning and push protection are on
— push protection would have refused the keypair commit that is still in
history. Dependabot alerts and security updates are on. `main` now refuses force
pushes and deletion.

Pull requests are deliberately **not** required: that would block the
push-to-deploy workflow in use, and it is a workflow decision rather than a
security patch. Still outstanding, and both are yours to click: **require a PR
review before merge**, and **2FA on the GitHub account**. A minimal CI running
`cargo test` would give the branch protection something to gate on.

Turning Dependabot on immediately surfaced 47 alerts — 39 in
`program/migration`, 7 in `program/scripts`, 1 in `Cargo.lock`. **None are in
the production worker or the site**; see INFRA-09.
**Priority:** ~~P1~~ partly done; the rest is account configuration.

### [MEDIUM] INFRA-05: Server errors return internal detail to the client
**Confidence:** 9/10 · **Phase:** 6 — OWASP A04/A09 · **Category:** Information disclosure
**Location:** `worker/src/index.js:2873`

**Description:** The catch-all handler returns the raw exception message:
```js
return json(request, env, { error: 'server error', detail: message }, 500);
```
D1 errors, upstream API errors and internal identifiers reach an unauthenticated
caller.

**Exploit scenario:** an attacker sends malformed bodies to each route and reads
the `detail` values to learn table names, column names, upstream providers and
which code path failed — the reconnaissance step that precedes a real attempt.

**Remediation:** keep logging the detail server-side (`logError` already does),
return only a reference to the client:
```js
return json(request, env, { error: 'server error' }, 500);
```
**Status:** FIXED 2026-09-12.
**Priority:** ~~P1~~ done.

### [MEDIUM] INFRA-06: Admin routes are unthrottled and compared non-constant-time
**Confidence:** 8/10 · **Phase:** 6 — OWASP A07 · **Category:** Auth failures
**Location:** `worker/src/index.js:1671, 1817, 1828, …` — 11 admin routes

**Description:** Admin auth is `auth !== 'Bearer ' + env.ADMIN_TOKEN` — an
early-exit string comparison — and **no rate-limit rule matches any
`/api/admin/*` path**. Guessing is unlimited. The admin surface can settle
missions, approve banner creative, mint plushie codes, and export the entire
database including customer names and contact details.

**Exploit scenario:** an attacker scripts guesses against `/api/admin/export`
with no throttle at all. Token entropy is the only defence; if it was ever set to
something short or memorable, this is reachable. A remote timing side channel on
Workers is unreliable, which is why this is 8/10 and not higher.

**Remediation:** add a strict rate rule for `/api/admin/*` (e.g. 5/min by IP),
and compare in constant time:
```js
function safeEqual(a, b) {
  if (a.length !== b.length) return false;
  let d = 0;
  for (let i = 0; i < a.length; i++) d |= a.charCodeAt(i) ^ b.charCodeAt(i);
  return d === 0;
}
```
Confirm `ADMIN_TOKEN` is ≥32 random characters; rotate it if unsure.

**Status:** FIXED 2026-09-12. All admin routes are throttled to 5 attempts a
minute per IP, checked **before** the token is read, and the comparison is now
constant time. Verified live: the sixth wrong-token attempt returns 429.
**Priority:** ~~P1~~ done.

### [MEDIUM] INFRA-07: Helius credits can be drained through the cleanup scanner
**Confidence:** 8/10 · **Phase:** 7 — STRIDE-DoS · **Category:** Economic denial of service
**Location:** `worker/src/index.js` — `/api/cleanup/scan` → `scanWallet()`

**Description:** `/api/cleanup/scan` takes **any** wallet address, is
unauthenticated, is not cached, and makes roughly four Helius calls per request
(two `getTokenAccountsByOwner`, `getAssetBatch`, prices). The limit is 20/min per
IP. `/api/img` is cached and bounded to 219 mints, so it is not the exposure —
this route is.

**Exploit scenario:** an attacker scans random wallets from rotating IPs (a cheap
proxy pool) at 20/min each — roughly 80 Helius calls per minute per IP. The free
tier's DAS limit is 2 requests per second. Credits exhaust or rate limits trip,
and then **holder analytics, the Ranger grid and wallet cleanup all fail for real
users** while the attacker spends almost nothing.

**Remediation:** cache scans by wallet for 60s (the Cache API is already used for
`/api/img`), and require a signed-in session for `/api/cleanup/scan` — the
feature is only useful to someone who has connected a wallet anyway. Consider
Cloudflare Turnstile on the unauthenticated entry points.

**Status:** FIXED 2026-09-12, though not the way this recommended. The route
stays public — it is worth being able to try before connecting a wallet. Instead
it is cached for 60s per wallet, and capped globally at 600 scans an hour. A
per-IP limit does nothing against a proxy pool; a global ceiling does, and it
fails closed with a message rather than draining quietly.

Caught while implementing it: caching the `Response` object itself would have
stored whichever CORS header the first caller got. A miss from a foreign origin
carries no `Access-Control-Allow-Origin`, so the next real request would have
been served that header-less response and the site would have broken. The cached
body is now re-wrapped with CORS computed for the actual caller — verified by
populating the cache from `evil.example` and confirming solquicks.com still
receives its header.
**Priority:** ~~P1~~ done.

### [LOW] INFRA-08: An abandoned program keypair is in public git history
**Confidence:** 10/10 · **Phase:** 1 — Secrets · **Category:** Secret exposure
**Location:** commit `873a858` (2026-09-01), `program/target/deploy/moon_stake-keypair.json`

**Description:** A 64-byte Solana secret key was committed and is still fetchable
without authentication from the public repo. It belongs to
`9vVtZ3Qdpz7JdbB5PwVdUmhPoVmUNwQuXeuRmpQxVpNJ`.

**Why this is LOW and not CRITICAL — verified, not assumed:**
- It is **not** the current program keypair. `declare_id!` is
  `DSWFRcF4Ky9Nw7RQUUa2M9nnXD4kRrbYGjegF7dyJ9B5`, whose keypair has never been
  committed (it is gitignored and untracked).
- **Nothing is deployed** at the leaked address on mainnet or devnet.
- Nothing in the current tree references it; it appears only in two 2026-09-01
  commits that were later superseded.

**Remediation:** treat `9vVtZ3Qd…` as permanently burned and never deploy to it.
Purging history (`git filter-repo`) is optional here precisely because the key is
worthless — but the underlying cause is worth fixing: `program/target/` is
gitignored **now**, and was not on 2026-09-01. Verify before every first push.
**Priority:** P2 — and never reuse the address.

### [LOW] INFRA-09: 16,690 dependency files are committed; the migration toolchain has known CVEs
**Confidence:** 9/10 · **Phase:** 2 — Supply chain
**Location:** `program/scripts/node_modules/` (tracked), `program/migration/`

**Description:** `node_modules` is committed under `program/scripts` — 16,690
files, and a 32 MB pack. Committed dependencies are invisible to `npm audit` in
the normal workflow and are not updated by `npm ci`. Separately,
`program/migration` reports 63 advisories (3 critical, 10 high), including
**`elliptic` — private key extraction from a malformed signing input** — and
`program/scripts` reports 29.

**Why this is LOW:** none of it ships to users. The production worker has no
dependencies and the site loads one pinned CDN script. The real exposure is
local: these scripts run on the laptop **with `uploader.json`**, the Arweave
funding key, in the same directory.

**Remediation:** `git rm -r --cached program/scripts/node_modules` and gitignore
it; `npm audit fix` in both tool directories; drop `@irys/upload*`, which no
script imports any more since the move to Turbo.

**Correction (2026-09-12):** removing Irys shrinks the tree but does **not**
clear the critical `elliptic` advisory — `@ardrive/turbo-sdk`, which *is* used,
pulls it in as well through `@cosmjs/crypto` and `@dha-team/arbundles`. The
durable mitigation is that the migration is finished: retire `uploader.json`
(sweep its balance and credits) so these scripts no longer sit beside a funded
key.

Dependabot is now enabled and reports these: 39 alerts in `program/migration`,
7 in `program/scripts`, 1 in `Cargo.lock` (the moon-draw `rkyv` advisory).
**Priority:** P2.

### [LOW] INFRA-10: 30-day bearer sessions in localStorage, never rotated
**Confidence:** 8/10 · **Phase:** 6 — OWASP A07
**Location:** `worker/src/index.js:7` — `SESSION_TTL_MS = 30 * DAY_MS`

**Description:** Session tokens are 256-bit and properly random, but live for 30
days in `localStorage` with no rotation and no server-side revocation path. Any
future XSS — or a shared/public machine — yields a month of authenticated access.
There is no XSS today, which is why this is LOW rather than MEDIUM.

**Remediation:** shorten to ~7 days, reissue on use, and add an admin route to
revoke a wallet's sessions.
**Priority:** P3.
